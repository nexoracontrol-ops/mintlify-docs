Welcome to NEXORA Core v1. This documentation covers **EK-021**, a deterministic admissibility decision engine implemented in parity across Python and TypeScript. Given canonical evidence and controls, EK-021 produces a byte-identical SHA-256 digest and the same admissibility decision in either language, verified by a shared test vector fixture.

## What EK-021 is

EK-021 is a pure decision engine. It takes a canonical input object (evidence anchors and control parameters), canonicalizes it with RFC 8785 JCS, hashes the result with SHA-256, and returns a `Decision` with one of three status values:

- `ADMISSIBLE_STATE_CONFIRMED` / `CONFIRM`
- `ADMISSIBLE_DEVIATION_DETECTED` / `CLAIM`
- `INADMISSIBLE_EVIDENCE_GAP` / `null`

## What EK-021 does not do

Per Protocol Lock L5, EK-021 is an admissibility decision engine only. It does not:

- Write economic state
- Authorize execution
- Execute
- Verify external outcome
- Settle
- Assign recovered value
- Issue Economic Receipt

Downstream capabilities (state machine integration, event store, external adapters, outcome verification, Economic Receipt) are gated by L7 and only apply once Python and TypeScript parity passes. See the full [Protocol Lock](/protocol-lock) for the conformance contract.
