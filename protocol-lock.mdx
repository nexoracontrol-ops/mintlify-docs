The Protocol Lock defines what makes an implementation of NEXORA Core v1 conformant. Every layer below (L0 through L7) is part of the contract that Python and TypeScript must both satisfy. Any implementation that produces a different digest or decision for a shared test vector is non-conformant.

<Warning>
  This document defines conformance. Changing any layer is a protocol change, not an implementation change.
</Warning>

## L0 Canonical input

Only these fields enter the EK-021 input digest:

- `evidence[].anchor_id`
- `evidence[].type`
- `evidence[].value`
- `evidence[].source`
- `evidence[].status`
- `controls[].key`
- `controls[].value`
- `controls[].source_clause`

No UUID, timestamp, runtime metadata, ordering generated by a map or object, or host-specific field is permitted in the canonical input.

## L1 Canonicalization

RFC 8785 JSON Canonicalization Scheme (JCS).

## L2 Digest

SHA-256 over the exact JCS UTF-8 bytes. The hex digest is the `input_sha256` field on every `Decision`.

## L3 Money

Protocol monetary values are decimal strings. TypeScript performs monetary arithmetic with `bigint` cents, not IEEE-754 `Number`. Python uses `Decimal` with `ROUND_HALF_UP` quantized to `Decimal("0.01")`.

## L4 Decision vocabulary

| status | resolution_type |
| --- | --- |
| `ADMISSIBLE_STATE_CONFIRMED` | `CONFIRM` |
| `ADMISSIBLE_DEVIATION_DETECTED` | `CLAIM` |
| `INADMISSIBLE_EVIDENCE_GAP` | `null` |

## L5 Authority boundary

EK-021 is an admissibility decision engine only. It does not:

- Write economic state
- Authorize execution
- Execute
- Verify external outcome
- Settle
- Assign recovered value
- Issue Economic Receipt

See [Authority Boundary](/reference/authority-boundary) for the full rule.

## L6 Shared vectors

`test-vectors/core-v1.json` is the protocol conformance fixture. Any implementation that produces a different digest or decision for the same vector is non-conformant. See [Test Vectors](/guides/test-vectors) for the three shipped cases and how to add new ones.
